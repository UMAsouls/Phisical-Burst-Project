# Physical-Burst-Project

Unityで制作した、SRPG風のコマンドバトルゲームです。

攻撃時には味方と敵がそれぞれ技を選択し、その組み合わせによって戦闘結果が変化します。
敵との相性や位置関係を考えながら有利な状況を作り、敵モンスターの全滅を目指します。

## 設計・実装で工夫した点

### 開発効率を高める設計

学祭までの2ヶ月でゲームを完成させるため、機能を追加する際の実装の手間を減らせる設計を意識しました。

カメラ制御など、ゲーム全体の様々な箇所から利用する処理はシングルトンで管理しています。
これにより、利用するオブジェクトごとに参照を保持・受け渡しする必要をなくし、必要な箇所から容易にアクセスできるようにしました。

また、コマンドからユニットのダメージ処理などを呼び出す際は、具体的な実装に直接依存させず、インターフェースを介して処理を実行する構造にしました。
これにより、コマンドやユニットに機能を追加する際の既存コードへの修正範囲を抑えています。

これらの設計によって機能追加にかかる手間を減らし、2ヶ月の開発期間で8種類のコマンド処理を実装しました。

### 初期コマンドと追加コマンドを統一して管理

当初はキャラクターのレベルによって使用できるコマンドが増える仕様を想定していました。

Prefabにあらかじめ設定されたコマンドと、ゲーム進行中に追加されたコマンドを別々に管理すると、コマンドを利用する側が両方のデータを意識する必要があります。

そこで、ユニット生成時に初期コマンドと追加コマンドを読み込み、ユニットが持つ1つのコマンドリストへ統合する仕組みを実装しました。

最終的にレベル制は採用しませんでしたが、この仕組みを利用することで、バトル終了後に新しいコマンドを獲得する仕様を容易に追加できました。

### Spriteアニメーション設定の再利用

使用したキャラクター素材は、4方向の歩行アニメーションが1枚のSprite Sheetとして出力される形式でした。

キャラクターごとにSpriteを切り分けてアニメーションへ登録すると、キャラクターを追加するたびに同じ設定作業が必要になります。

そこでShader Graphを用いてSprite用Shaderを作成し、**マテリアルパラメータからSprite Sheet内の表示領域を変更できる仕組み**を実装しました。

アニメーションではSpriteそのものを切り替えるのではなく表示領域パラメータを変更するため、画像を差し替えても同じ歩行アニメーション設定を再利用できます。

### UniTaskによるゲーム進行制御

SRPGでは、入力待ち・移動完了待ち・演出待ちなど、処理の途中で待機する場面が多く存在します。

これらを複数のイベントやコールバックで管理するとゲーム進行の流れが追いづらくなるため、UniTaskを用いた非同期処理を採用しました。

これにより、

`入力待ち → 行動実行 → 移動完了待ち → 状態遷移`

といった一連の処理を、実行順序に沿って記述できるようにしています。

また、移動中に相手の行動を停止させるなど、途中で発生する処理も組み込みやすい構造にしました。
